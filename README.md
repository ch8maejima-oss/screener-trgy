# スクリーニング銘柄抽出（screening-site）

株式会社トリロジー — 社内利用。外部公開はしていない。

東証プライム市場・スタンダード市場の内国普通株式を母集団として、6条件のスクリーニングを
機械的・網羅的に適用し、条件を満たした銘柄を全件出力する。

## スクリーニング条件

| # | 条件 | 閾値 | データ出所 |
|---|---|---|---|
| 1 | 配当利回り | 3.5% 以上 | 直近12か月の実績配当合計（分割調整済み）÷ 直近終値 |
| 2 | ROE | 10% 以上 | 有報【主要な経営指標等の推移】の自己資本利益率（開示値） |
| 3 | 自己資本比率 | 50% 以上 | 同上（開示値） |
| 4 | 流動比率 | 200% 以上 | 連結貸借対照表の流動資産 ÷ 流動負債 |
| 5 | 売上高 | 直近5期（4年間）で減収していないこと | 同【主要な経営指標等の推移】の売上高5期分 |
| 6 | 売上高営業利益率 | 10% 以上 | 連結損益計算書の営業利益 ÷ 売上高 |

条件2・3・5は当方で再計算せず、企業が有報で開示した値をそのまま採用する。

### 配当に有報の開示値を使わない理由

条件1だけは有報の「1株当たり配当額」を用いていない。期中に株式分割があると、
有報の値は中間配当が分割前・期末配当が分割後の基準のまま合算されるため、
分割後の株価と組み合わせると利回りが実態より大きく出る。
（例: ニトリHDは有報92.4円だが分割調整後は30.8円。利回りは3.6%ではなく1.2%）

そこで株価と同じ分割調整済みの系列から、直近12か月に実際に支払われた配当の合計を用いる。
株式分割のない銘柄では有報の開示値と完全に一致することを確認済み。
有報の開示値は `dps_yuho` 列に併記し、乖離率 `dps_diff_pct` で分割・期ズレを検知できる。

なお実績ベースであるため、前期に記念配当・特別配当があった銘柄は
翌期の会社予想より高い利回りとして計上される点に留意する。

### 対象外の扱い

判定に必要な数値が開示から取得できない銘柄は `算出不能により対象外` として件数を記録する。
個別銘柄を裁量で除外することはしない。主にこの区分に入るのは次の3つ。

- 銀行・保険など、貸借対照表に流動/固定の区分を持たない業種（条件4が算出できない）
- 米国会計基準の適用会社。連結財務諸表がXBRLタグ化されていないため条件4・6が取れない
- 上場から日が浅く、5期分の売上高が開示されていない会社（条件5が算出できない）

### 連結・単体の扱い

書類ごとに連結ベースか単体ベースかを1つ決め、全項目をそのスコープでのみ取得する。
項目ごとに連結→単体のフォールバックを行うと、分子が連結・分母が単体という
食い違いが起き、比率が実態とかけ離れる（実装当初、連結の営業利益を単体の売上高で
割っていた銘柄があった）。連結で取れない項目は単体で代用せず算出不能とする。

スコープは書類の内容から判定する。EDINETコードリストの「連結の有無」欄は
実態と一致しない場合があるため、判定には用いない。

## デイトレード用スクリーニング（/daytrade）

配当重視6条件とは別に、短期売買向けの2リスト（買い候補・空売り候補）を提供する。
「前日+2〜10%」（上昇）と「前日-2〜-10%」（下落）は同時に成立しない対の条件のため、
上昇モメンタム・下落モメンタムの2リストに分けている。

**共通条件**（両リストとも必須）

| 条件 | 基準 | データ出所 |
|---|---|---|
| 対象市場 | 東証プライム・スタンダード | JPX「東証上場銘柄一覧」 |
| 信用区分 | 貸借銘柄（空売り可能） | JPX「制度信用・貸借選定銘柄一覧」 |
| 株価 | 500円以上 | 直近終値 |
| 売買代金 | 50億円以上 | 直近終値 × 直近出来高 |
| 出来高 | 増加傾向（直近5日平均 > 直近20日平均） | 直近の日次出来高 |

**買い候補（上昇モメンタム）固有条件**: 前日騰落率 +2〜+10% ／ 20日騰落率 +10%以上 ／ 5日騰落率 +5%以上

**空売り候補（下落モメンタム）固有条件**: 前日騰落率 -10〜-2% ／ 20日騰落率 -10%以下 ／ 5日騰落率 -5%以下
（下落側の20日・5日条件は、依頼時の原案に数値が無かったため上昇側条件をミラーして補完したもの）

時価総額500億円以上の銘柄は除外せず、一覧の並び順で優先表示する（`is_large_cap`列）。

### 実行手順

```bash
python3 scripts/fetch_margin_list.py        # 貸借銘柄一覧を取得 -> data/master/margin_list.csv
python3 scripts/screen_daytrade.py          # 株価・出来高を取得して判定
python3 scripts/build_daytrade_site_data.py # 閲覧UI用データを生成
```

`fetch_margin_list.py` はJPXの一覧ページから当月分のxlsxリンクをスクレイピングして取得する
（ファイル名が毎月変わるため固定URLでは取得できない）。JPXは毎月第1営業日に更新するが、
キャッシュ管理を避けるため日次バッチで毎回フルフェッチしている。

### 出力

| ファイル | 内容 |
|---|---|
| `output/daytrade_buy_YYYY-MM-DD.csv` | 買い候補（全件） |
| `output/daytrade_short_YYYY-MM-DD.csv` | 空売り候補（全件） |
| `output/daytrade_all_judgements_YYYY-MM-DD.csv.gz` | 母集団全銘柄の判定内訳（gzip圧縮） |
| `output/daytrade_summary_YYYY-MM-DD.json` | 件数サマリと閾値 |

### 時価総額の算出

発行済株式数は有報の要素ID `jpcrp_cor:TotalNumberOfIssuedSharesSummaryOfBusinessResults`
（コンテキスト `CurrentYearInstant_NonConsolidatedMember`。DPSと同じく常に提出会社側にある）
から取得し、`financials.csv` の `shares_issued` 列に格納する。直近終値との積で時価総額を算出する。

## データ出所

- **銘柄マスタ**: JPX「東証上場銘柄一覧」(data_j.xls)
- **財務データ**: EDINET API v2（金融庁）— 有価証券報告書のXBRL（CSV形式）
- **株価**: yfinance（直近終値、デイトレード用は直近2か月のOHLCV）
- **貸借銘柄**: JPX「制度信用・貸借選定銘柄一覧」(xlsx、毎月更新)

## セットアップ

```bash
pip install -r requirements.txt
```

EDINET APIキーを https://api.edinet-fsa.go.jp/api/auth/index.aspx?mode=1 で取得し、
`screening-site/.env` に記載する（`.env` はGit管理対象外）。

```
EDINET_API_KEY=取得したキー
```

## 実行手順

```bash
cd screening-site

# 1. 銘柄マスタ構築（年1回程度／市場区分の変更時）
python3 scripts/build_universe.py
python3 scripts/build_edinet_map.py

# 2. 有報の取得（年1回程度。どちらも再開可能）
python3 scripts/fetch_edinet.py index      # 書類一覧を走査してdocIDを収集
python3 scripts/fetch_edinet.py fetch      # XBRL(CSV形式)を一括ダウンロード

# 3. 解析して財務スナップショットを生成
python3 scripts/parse_edinet.py

# 4. スクリーニング実行（日次。株価のみ再取得される）
python3 scripts/screen.py

# 5. 閲覧UI用のデータを生成
python3 scripts/build_site_data.py
```

有報は年1回しか更新されないため、2〜3は決算期後にまとめて実行する。
日次で変動するのは株価＝条件1のみなので、平常運転では4だけを回す。

## 出力

| ファイル | 内容 |
|---|---|
| `output/screening_YYYY-MM-DD.csv` | 全条件を満たした銘柄（全件） |
| `output/all_judgements_YYYY-MM-DD.csv.gz` | 母集団全銘柄の条件別判定内訳（gzip圧縮） |
| `output/summary_YYYY-MM-DD.json` | 母集団件数・条件別充足数・算出不能件数 |

`all_judgements` と `summary` は、条件を機械的・網羅的に適用したことの記録として残す。

### 初回実行の結果（2026-08-02 基準）

| 区分 | 件数 |
|---|---|
| 母集団（有報を取得し銘柄コードを特定できたもの） | 3,100 |
| 全条件充足 | 89 |
| 不通過 | 2,664 |
| 算出不能により対象外 | 347 |

条件別の充足件数は 配当858 / ROE1,182 / 自己資本比率1,845 / 流動比率1,571 /
売上高2,430 / 営業利益率836。ユニバース3,115社のうち13社は直近1年に有報の提出が
確認できず、2社は書類に銘柄コードが記載されておらず、母集団から外れている。

### EDINETのXBRLで注意を要する点（実データ3,102社で確認済み）

- 自己資本比率・ROEは百分率ではなく小数で格納される（0.5727 = 57.27%）
- 自己資本比率は Instant（時点）、ROEは Duration（期間）のコンテキストを持つ
- 1株当たり配当額は連結側になく、常に提出会社（`_NonConsolidatedMember`）側にある
- `jpcrp_cor:EquityToAssetRatioIFRSSummaryOfBusinessResults` は要素IDに反して
  中身が1株当たり親会社所有者帰属持分（BPS）。自己資本比率として使ってはならない。
  IFRSの自己資本比率は `RatioOfOwnersEquityToGrossAssetsIFRS...`
- IFRSの流動負債は `CurrentLiabilitiesIFRS` ではなく `TotalCurrentLiabilitiesIFRS`
- IFRS移行会社は期によって売上高の要素IDが変わるため、5期分は期ごとに候補を横断して探す

## 閲覧UI

`app/` に Next.js（App Router）の静的サイトを置いている。公開先は
**screener.trgy.co.jp**。ホスティングは **XServer Static**（エックスサーバーが無料提供する
静的サイト専用サービス）で、Vercelは使わない。手順は `DEPLOY.md` を参照。

投資家の資力・スタイルによってスクリーニング条件は異なるため、トップページ（`app/page.tsx`）は
各スクリーニング条件への入口を並べたハブページとし、条件ごとの結果はサブディレクトリに分けている。
現時点では配当重視の6条件スクリーニングを `app/dividend/`（`/dividend`）、デイトレード用の
買い候補・空売り候補2リストを `app/daytrade/`（`/daytrade`）に実装済み。スイング用など他の条件は
今後追加予定。

`scripts/build_site_data.py` / `scripts/build_daytrade_site_data.py` がそれぞれの最新結果を
`app/dividend/data/latest.json` / `app/daytrade/data/latest.json` に変換し、各ページはビルド時に
それを取り込む。APIは持たない完全な静的サイト。

各ページは、条件を機械的・網羅的に適用したことが読み取れるよう共通の構成にしてある。

1. 選定条件（条件・閾値・算出方法・条件別の充足件数と算出不能件数）
2. 条件に合致した銘柄の一覧（全件。並べ替え・市場／業種の絞り込みは表示上の操作）
3. 母集団と内訳（母集団・充足・不通過・算出不能の件数と、対象外とした理由）
4. データの出所と免責事項

`app/layout.tsx` に `robots: "noindex"` を設定済み。社内利用の間は解除しない。

### ローカルでの確認

Node.js 22 を `~/.local/opt/node22` にインストール済み（sudo不要のユーザー領域）。

```bash
export PATH="$HOME/.local/bin:$PATH"
npm run dev     # http://localhost:3000
npm run build   # out/ に静的ファイルを書き出す
```

### 自動更新

`.github/workflows/daily.yml` が毎営業日18:30(JST)に株価・配当を取得して再判定し、
サイトをビルドしてXServer StaticへFTP転送する。財務データの再取得は
`refresh-financials.yml` を年1回手動実行する。

## 未確定・要検討事項

- **財務データの鮮度**: 有報ベースのため年1回更新。最大で約1年前の数値になる。
  半期報告書での補完は未実装。
- **外部公開する場合**: 公開前に `compliance-reviewer` によるチェックが必須。
  商号・登録番号（近畿財務局長（金商）第372号）・加入協会名の明記、
  選定条件と除外基準の明示、断定的判断を含まない表現への統一が必要。
